# Open Questions & Blockers

## 1. Direct GPU Benchmarking Blocked (GLIBC Mismatch)
**Context:** We cannot directly run the Parabricks binary (`pbrun`) on the current SageMaker / Ubuntu 20.04 environment because the pre-compiled binary requires GLIBC 2.34 (which comes with Ubuntu 22.04), while the current system only provides GLIBC 2.31.
**Decision Needed:** Should we migrate the environment to an Ubuntu 22.04 Docker container with `--gpus all` configured, or rely solely on literature-based scaling metrics for the final presentation?

## 2. Mutect2 / Branch B Synthetic BAM Limitations
**Context:** The Mutect2 target variant pipeline (Branch B) resulted in a 0% recall because the synthetic BAMs were generated by spiking targets into the GRCh38 reference without generating a matched normal BAM. Mutect2 aggressively flags all calls as artifacts or germline when run in tumor-only mode without a normal panel.
**Decision Needed:** Do we want to download matched normal samples for the 29 target patients to properly calculate precision/recall, or explicitly document this as a pipeline design limitation?

## 3. High Class Imbalance in ML Task
**Context:** The ML model task has been successfully redefined to predict whether a variant is a CancerHotspot. While the ROC-AUC is excellent (0.987), the Precision-Recall AUC (PR-AUC) sits at 0.268. This is primarily because the dataset is extremely imbalanced (248 positive hotspots out of 62,143 total variants).
**Decision Needed:** Is this acceptable for the current scope, or should we implement synthetic oversampling (SMOTE) or adjust class weights heavily to prioritize recall of actionable variants?
